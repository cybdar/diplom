# План тестирования мобильного приложения «ВХОСПИСЕ»

## 1. Описание приложения

Приложение «ВХОСПИСЕ» состоит из следующих экранов:

- **Экран авторизации** — вход с логином и паролем.
- **Главный экран (Main)** — отображает 3 последние активные новости (свернутый блок). Неактивные новости не отображаются. У каждой новости указана дата публикации и иконка категории (например, для «Дня рождения» отображается торт). Доступно сворачивание/разворачивание всего блока новостей. У каждой новости есть кнопка для разворачивания/сворачивания полного описания. При нажатии на **All news** происходит переход в раздел **News**, где видны все новости.
- **Раздел News** — полный список всех новостей, сортировка, фильтрация по категории и дате.
- **Control Panel** — управление новостями: создание, редактирование, удаление, изменение статуса. Доступна фильтрация по категории, дате и статусу (активные / неактивные / все). При редактировании можно изменить категорию, заголовок, дату публикации, время, описание и статус (активность через ползунок). Также присутствуют поля **Creation date** и **Author**, которые не редактируются. **Обнаружен баг:** дата создания (`Creation date`) отображается некорректно (например, 12.07.58551 вместо фактической даты создания — 01.08.2026). **Обнаружен баг:** при фильтрации без выбора статуса (активный/неактивный) система показывает все новости, хотя должна требовать выбора.
- **Раздел Love is all** — список цитат о хосписе (только чтение). Каждая цитата отображается в виде краткого заголовка, при нажатии раскрывается полный текст. Автор цитаты отображается не у всех (иногда указан внутри заголовка или описания).
- **Выход** — через иконку человечка → Log out.

## 2. Границы тестирования

- **Тестируем:** клиентскую часть приложения (UI, навигацию, функциональность).
- **НЕ тестируем:** серверную часть, производительность, безопасность.

## 3. Виды тестирования

- **Функциональное:** проверка работы всех кнопок, полей, переходов.
- **UI/UX:** проверка отображения элементов.
- **Регрессионное:** прогон автотестов после изменений.

## 4. Планируемые сценарии для автоматизации

Список тест-кейсов, которые планируется автоматизировать:

- **TC-01** — Успешная авторизация (High)
- **TC-02** — Авторизация с пустыми полями (High)
- **TC-03** — Авторизация с неверным паролем (High)
- **TC-04** — Открытие раздела News (High)
- **TC-05** — Открытие раздела Love is all (Medium)
- **TC-06** — Применение фильтра новостей (High)
- **TC-07** — Создание новости (позитивный сценарий) (High)
- **TC-08** — Создание новости с пустым заголовком (Medium)
- **TC-09** — Создание новости с пустым описанием (Medium)
- **TC-10** — Редактирование новости (High)
- **TC-11** — Удаление новости (High)
- **TC-12** — Изменение статуса новости на Not active (Medium)
- **TC-13** — Выход из аккаунта (High)

## 5. Данные для входа

- **Логин:** login2
- **Пароль:** password2
- **Невалидные данные:** пустые поля, неверный пароль.
- **Обнаруженный баг:** приложение пропускает пробелы в начале и конце логина/пароля (не обрезает их). Ожидаемое поведение — либо автоматическая обрезка пробелов, либо ошибка `"Something went wrong. Try again later."` (как при вводе неверных данных). Текущее поведение является багом, так как снижает безопасность и вводит пользователя в заблуждение.

## 6. Инструменты

- **Android Studio** (среда разработки).
- **Espresso** (фреймворк для UI-автотестов).
- **Allure** (генерация отчётов).
- **Эмулятор:** Android API 36.

## 7. Интервальная оценка с учётом рисков

Оценка времени на выполнение работ (в часах):

- **Ручное тестирование** (составление чек-листа и тест-кейсов) — 4-6 часов
- **Настройка проекта** (добавление зависимостей, создание папки androidTest) — 1-2 часа
- **Написание автотестов** (написание 10-15 тестов на Espresso) — 6-10 часов
- **Отладка тестов** (исправление ошибок, стабилизация) — 4-6 часов
- **Allure и отчёты** (подключение Allure, генерация отчёта) — 2-3 часа
- **Итого с учётом рисков** (сервер недоступен, баги в приложении) — 20-30 часов

## 8. Этапы работы

1. Ручное тестирование (составление чек-листа и тест-кейсов).
2. Написание автотестов.
3. Сделать отчёт в Allure.
